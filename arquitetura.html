Document Factory

Um lote escaneado com centenas de páginas entra. Saem documentos separados, classificados por tipo e pesquisáveis, com os dados pessoais tarjados. Tudo que a máquina não tem certeza vai para uma pessoa revisar.

  • FastAPI
  • PyMuPDF
  • Tesseract · por
  • PostgreSQL 16
  • MinIO / S3
  • modelo via API OpenAI-compatível
  • Angular
  • Docker Compose

Role para os lados ou ajuste à tela

Do upload à revisão

A API só recebe o arquivo e cria uma linha por página no banco. Quem faz o trabalho pesado são os workers, que pegam uma página de cada vez. Por isso dá para matar um worker no meio do lote e ele retoma de onde parou.

Como o sistema decide onde um documento termina

O sistema avalia cada página contra os sinais abaixo, do mais forte para o mais fraco, e para no primeiro que se aplica. A confiança do documento é a menor entre a confiança do tipo, a de cada corte e a qualidade do OCR.

Sinal na páginaDecisãoConfiança do corte
Página em brancoseparador: fecha o documento atual—
Primeira do lote ou logo após um separadorinício0,95 com título · 0,85 sem
“Página 2 de 3”, “fl. 2/3”continuação0,97 · 0,60 se título ou modelo dizem início
“Página 1 de N”início0,97
Título do tipo no topo (30% superior)início0,90 · 0,60 se o modelo diz continuação
Só o modelo diz que é inícioinício0,75
Tipo mudou, com confiança ≥ 0,6início0,65
Mesmo tipo do documento atualcontinuação0,90
Tipo desconhecidocontinuação0,80
Tipo diferente com confiança baixacontinuação0,60

Vai para a fila de revisão quando a confiança fica abaixo de 0,80, o tipo é desconhecido, regras e modelo discordam, a contagem “1 de N” não bate com o número de páginas encontradas ou alguma página falhou. Os outros documentos ficam como auto_aprovado.

Estados e retomada após falha

Cada página tem um status no banco. Um worker que morre deixa a página como “processando”. Depois de 2 minutos ela volta para a fila, e reprocessar a mesma página não duplica nada.
